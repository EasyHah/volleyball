# CHG-20260728-002：Unity 6000.3 项目升级

- 日期：2026-07-28
- 状态：已完成
- 负责人：Project / Packages / Docs
- 影响模块：ProjectSettings / Packages / Docs
- 交互级别：模块内部
- 关联分支：`main`
- 关联提交或 PR：本记录所在提交

## 改动摘要

将主分支 Unity Editor 从 `6000.0.43f1 (97272b72f107)` 升级到
`6000.3.20f1 (c9ba695d4f07)`，并接受 Unity 6000.3 首次打开项目生成的 package
迁移结果。

## 具体变更

- `ProjectVersion.txt` 更新到 `6000.3.20f1`；
- `com.unity.nuget.newtonsoft-json` 从 `3.2.1` 更新到 `3.2.2`；
- Unity Test Framework 从 registry `1.1.33` 更新到 6000.3 内置 `1.6.0`；
- manifest 补齐 6000.3 解析出的内置 adaptive performance 与 vector graphics
  模块及其 lock dependencies；
- README 和当前开发操作指引改用 Unity `6000.3.20f1`；历史变更记录中的
  `6000.0.43f1` 测试环境保持原样。

## 版本边界

本次只升级 Unity Editor 与 package resolution，不修改：

- 产品 `bundleVersion`（继续为 `1.0`）；
- Match/Result 和 Replay V4 contract；
- Full Rally V3 rules；
- canonical serialization、hash 或 gameplay 配置。

## 跨模块交互重点

无合同或数据迁移。所有开发者需使用 Unity `6000.3.20f1` 打开主分支，并让 Package
Manager 使用已提交的 manifest/lock，不要用 6000.0 重新写回项目版本。

## 验证

- Unity 6000.3 EditMode：745/745 passed，0 failed/skipped/inconclusive，
  8.6392464s（`TestResults/Main-Unity6000.3-final-editmode.xml`）；
- Unity 6000.3 PlayMode：39/39 passed，0 failed/skipped/inconclusive，
  323.1839383s（`TestResults/Main-Unity6000.3-final-playmode.xml`）；
- 首次迁移和两套测试均完成 package resolution，无编译或场景加载错误；
- `git diff --check` clean。

## 回滚与风险

回滚必须同时恢复 `ProjectVersion.txt`、manifest 与 packages lock。主要风险是 Test
Framework 版本变化引起 runner 行为差异，以及 Unity 6000.3 的场景/序列化兼容性；
通过完整两套测试验证。
