# CHG-20260717-003：建立统一改动文档流程

- 日期：2026-07-17
- 状态：已完成
- 负责人：多方
- 影响模块：Docs
- 交互级别：协作流程（重点）

- 关联提交或 PR：本文件所在提交

> [!IMPORTANT]
> 从本次改动开始，Match 与 Career 两边的实现改动都必须在 `docs/changes/` 建立记录。
> 涉及 Shared、Bootstrap 或要求对方同步的改动，必须在索引和正文中标为“跨模块（重点）”，
> 并明确写出对方需要执行的事项。

## 改动摘要

新增统一改动索引、可复制模板和跨模块重点标注规则，并补录已有的 Shared 契约边界与
Unity 模块迁移记录。

## 具体变更

- 统一入口：`docs/changes/README.md`
- 标准模板：`docs/changes/TEMPLATE.md`
- 文件命名、编号、状态和索引维护规则
- 跨模块交互的判定条件与强制重点标注格式
- 既有 Match 原型计划和设计稿迁入 `docs/changes/archive/match-prototype/`
- 当前 Match/Career 统一模块路线图迁入 `docs/changes/unified-unity-modules-plan.md`

## 跨模块交互重点

- 接口提供方：各改动负责人
- 接口使用方：Match 与 Career 两边开发者及评审者
- 数据方向：不涉及运行时数据；属于开发协作流程
- 兼容性：不影响游戏运行
- 对方开发者需要做什么：后续每个实现改动都复制模板、更新索引；跨模块改动必须填写
  交互提供方、使用方、兼容性和同步动作

## 验证

- 已检查三份改动记录均进入索引
- 已检查跨模块记录包含醒目重点区块和对方行动项
- 不涉及 Unity 运行时代码，无需重复运行 Unity 测试

## 回滚与风险

流程本身没有运行时风险。主要风险是索引遗漏或文档与实现不同步；Pull Request 评审时应
把改动文档链接和代码测试结果作为同一组交付物检查。
