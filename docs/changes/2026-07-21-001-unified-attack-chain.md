## 改动摘要

统一 3v3 与正式 6v6 的二传到进攻链路，让计划击球点、二传目标和真实手掌接触中心使用
同一份物理计划；加入二传节奏求解、真实触球后重规划、A-E 二传质量、责任归因、统计和
回放诊断。同时加入 50 分绝对封顶：任一方先到 50 分立即获胜，不再要求两分分差。

拦网接触改为跟随可见模型的双侧上臂、前臂和手掌六个扫掠胶囊。头、躯干、髋、腿和脚
不参与拦网触球；Unity Collider 仍不作为比赛物理权威。

## 具体变更

- Shared 新增 `PlayerAbilitySnapshotV2`、`PlayerSnapshotV2`、`TeamSnapshotV2`、
  `MatchContextV2` 和 `MatchResultV2`，其中 `MaxAttackReach` 合法范围为 3.20–3.55 米。
- V1→V2 默认摸高：防守/自由人/二传 3.20 米，主攻/接应 3.42 米，副攻 3.48 米；
  这些仅是旧数据迁移默认值，不限制 V2 球员个体能力。
- 3v3 和 6v6 新比赛使用 V2；旧 `Initialize` 与 V1 结果链路保留，V2 使用独立
  `InitializeV2`，避免空参数重载歧义。
- `AttackContactPlan` 统一起跳点、击球中心和摸高；`SetFlightSolver` 在节奏范围内按
  固定步长求解可达飞行时间，实际二传触球后重新规划进攻或降级为处理球。
- 质量、重规划、处理球、责任和相关统计写入现有回放事件，不新增不兼容的回放版本。
- V1/V2 上下文与结果实现共同只读接口，Career 边界可显式接收任一版本；历史回放新增字段
  均省略默认值，旧 JSON 形状和校验和保持不变，结算原因与责任球员可完整回放。
- D/E 级处理球保留真实低位触球高度，并给低位回球设置物理可越网的最短飞行时间；快攻
  在二传触球前完成可计算的预助跑并预留反应时间，避免把物理不可达的助跑误判为可完成。
- 攻击手掌显式支持双面扫掠接触，使手掌从球后方追上二传球时仍能物理触球；接球、二传、
  发球和环境接触继续使用原有单面规则。
- `MatchSetRules` 的 50 分为绝对上限；50:49 是合法终局，先到 50 的一方获胜。
- 拦网者中心距中线 0.18 米，动作开始时重新面向球网；可见双臂前压、内收，六个胶囊
  共用一个触球组，重叠部位每固定步最多接受一次 `Block`。

## 跨模块交互重点

- 接口提供方：Shared
- 接口使用方：Match；Career 可选择继续使用 V1 或显式接入 V2
- 数据方向：`Career -> Shared MatchContextV1/V2 -> Match -> Shared MatchResultV1/V2 -> Career`
- 兼容性：兼容。V1 类型、历史 JSON 固定样本和规范哈希保持不变；V2 使用独立类型、
  JSON 方法和哈希，不会被静默当成 V1。
- 对方开发者需要做什么：现有 V1 调用无需改代码；新建比赛若需要个人摸高，请提供 V2
  球员能力并调用 `InitializeV2`。读取结果时按启动时选择的版本接收 V1 或 V2。

## 回滚与风险

主要风险是近网拦网姿态改变长期比赛中的拦网分布，以及调用方误把 V2 当作 V1。观察
`PhysicalBlockContacts`、A级后无触球率、对称胜率和 V1 固定样本。代码可按提交边界回滚：
V2 合约、统一进攻链、全手臂胶囊和近网站位均有独立提交；不要通过放大胶囊或降低校准
阈值规避结构问题。
