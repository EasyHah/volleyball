## 改动摘要

正式 6v6 场景现在可以把一个完整回合记录为经过校验的 `MatchReplayV1` JSON，
并在同一目录生成可交互的 HTML 查看器。回放保存 10 Hz 常规状态、每个事件的精确快照、
十二名球员、球、比分、发球队、轮转、球权和完整决策候选得分，不需要重新运行比赛物理。

本次只捕获自动化测试中的首个完整回合，不提供整局录制、视频、Unity 回放场景、网络传输
或 `TestResults/` 之外的持久化。Shared、Career、Bootstrap 和 Build Settings 均未修改。

## 具体变更

- 文件、场景、资源或程序集：
  - 新增 Unity-free 的 `Domain/Replay/MatchReplayV1.cs` 与 `MatchReplayJson.cs`，定义 V1 DTO、
    严格校验、规范化载荷和 SHA-256 内容校验和。
  - 新增 `MatchReplayRecorder`，只读观察 `PhysicalMatchRallyDirector` 与 `SimulatedBall`，
    在捕获起点基础上用整数采样序号生成 0.1 秒刻度，并在事件前补齐常规采样。
  - 新增 `MatchReplayArtifactWriter`，写出 `replay.json` 与内联 CSS/JavaScript 的
    `index.html`；HTML 优先读取同目录 JSON，直接以 `file://` 打开时可回退到内嵌副本。
  - 新增合同 EditMode 测试与正式 6v6 首回合 PlayMode 测试；产物写入忽略目录
    `TestResults/decision-replay/<run>/`。
- 新增或修改的公开类型/字段：
  - `MatchReplayV1` 固定 `formatVersion=1`、`sampleIntervalSeconds=0.1`，未知版本、非有限值、
    非单调时间、无效玩家或快照引用、事件顺序及校验和错误均被拒绝。
  - Director 新增只读回放事件和比分、发球队、轮转、球权访问器；`SimulatedBall` 新增
    固定步完成通知。现有 `DecisionPlanned`、比赛规划、物理响应、计分和时间倍率不变。
- 行为变化：
  - 接触事件使用真实物理接触时间；同一步中的常规采样、接触、决策和结算保持单调顺序。
  - HTML 显示 9×18 米俯视场地、十二名 `TEAM P1-P6 ROLE` 标签、球员朝向、球、比分、
    发球队、轮转、阶段和时间；支持播放/暂停、0.5×/1×/2×、拖动时间轴和前后事件。
  - 播放到 Decision 自动暂停，候选面板显示六名球员的可达、角色、助跑、角度、技术与总分，
    并区分选中、不可达和连续触球排除状态。普通快照之间插值，事件边界不插值。

## 回滚与风险

10 Hz 采样优先控制文件体积，普通动画不是连续物理轨迹；所有接触、决策和结算边界仍有
独立事件快照。未来整局或多局录制应分段或流式写入，避免一次把大型文档加载到内存。

回滚时先移除 HTML writer 与产物测试，再移除 recorder、只读事件和 Replay Domain。
回放观察器不参与比赛决策或计分，因此可以独立回滚；无需迁移 Shared 或 Career 数据。
