# 比赛规则单一事实源

**状态：** 规范性文档
**适用范围：** `Assets/Volleyball/Match/` 的运行时比赛、AI 决策、物理模拟、回放和测试。

本文件是项目比赛规则的唯一规范性来源。代码、测试、设计规格和变更记录必须遵守本文件；它们可以说明实现和验证，但不得另行定义、复制或悄然改变规则。

## 治理与优先级

1. 本文的裁判不变量优先于 AI、动画、表现、回放和任何外部建议。
2. 本文的规则 ID 是唯一的。同一目的只能有一条规范性规则；需要细化时更新该规则，而不是新增平行表述。
3. 设计规格必须链接相应规则 ID，只描述实现方案、边界和验收；变更记录只描述历史变化；二者均不具有规则权威。
4. 代码和测试若与本文冲突，应视为缺陷。无法同次修复的遗留行为必须在“符合性清单”中登记，不能通过修改文字把它合法化。
5. 任何规则修改必须同时更新：本文件、直接受影响的 EditMode/PlayMode 测试、实现位置和关联规格；提交前须检查规则 ID、重复条款和冲突条款。

## 确定性与决策边界

### R-GOV-001 禁止硬随机

比赛规则、战术意图、选人、传球目标、进攻线路、拦网人数和判分不得以概率分支、随机抽样或“为了变化而故意选择次优方案”决定。相同的比赛状态和配置必须生成相同的决定及结果。

允许的执行差异只能来自可追溯的能力、疲劳、动作姿态、可达性、物理接触及其已序列化的执行误差输入。固定种子只能用于重放同一份已定义的执行误差，不能替代状态驱动的规则决策。

### R-GOV-002 本地权威

LLM、联网来源和表现层只能提出有界战术偏好，不能直接设置球速、变换球员位置、绕过触球合法性、物理碰撞、可达性或裁判判分。无效、超时或异常输入必须回退到本地确定性决策。

## 裁判与回合不变量

### R-REF-001 一回合一分

每个完成回合恰好结算一分。比赛结束后不再调度新回合或修改比分。

### R-REF-002 触球资格与次数

Receive、Set 和 Attack 是计数触球：只能由当前持球队完成；同一球员不得连续完成两次计数触球；每个球权最多三次，第四次为犯规。触球还必须处于对应的有效时间窗、队伍、动作和候选球员范围内；非法候选必须在改变球速前被拒绝。

### R-REF-003 拦网触球

Block 是物理触球并更新最后触球球员/队伍，也计入该球员的接触和负荷统计；它不消耗本队三次计数触球。一个物理事件最多接受一次 Block，即使多段手臂或多个拦网者同时覆盖球。

### R-REF-004 拦网后的回合边界

接受 Block 后不得立即为任何一方创建接球球权。球继续接受既有越网、标志杆、界内界外和落地判定：合法越网后才由接球方开始零次触球的新球权；在此之前的落地由最后触球方（拦网方）按 R-REF-005 结算。

### R-REF-005 落点与越网判分

最后触球方使球在对方界内落地即得分；球落在己方界内、界外或越过标志杆区间，则对方得分。触网本身可以继续比赛，只要后续合法越网和落点成立。拦网、手臂边缘碰撞和其他折射只改变物理轨迹，不创建额外判分规则。

### R-REF-006 发球、轮转与单局结束

接发方赢球后获得发球权并顺时针轮转；当前发球方赢球不轮转。3v3 目标 15 分、6v6 目标 25 分，均需领先 2 分；达到 50 分绝对上限立即结束。6v6 的 P1 发球，P2--P4 为前排。

## 场地、角色与可达性

### R-PLAY-001 场地边界

球员根节点必须在本方场地内，保留既定的边线和球网安全余量；合法扣球和拦网时肢体可越过网面。世界坐标固定为 X 左右、Y 高度、Z 场地深度；队伍局部坐标只能镜像 Z，不能镜像 X。

### R-PLAY-002 角色是偏好

角色提供选人偏好而不是动作锁。可达性、触球合法性和物理时间窗优先于名义角色；可达球员可接、传、攻、拦或补防。6v6 主动拦网候选额外限于前排，3v3 无前排限制。

### R-PLAY-003 多人拦网

防守方按预测截击点与可达性选择一至三名不同的拦网者。主拦覆盖中心截击点，协防拦网者只在能于时间窗内到达相邻横向通道时加入；不可达者不得瞬移或仅为凑人数加入。

## 组织、助跑与进攻

### R-OFF-001 二传组织深度

距网不超过 1.50m 是最佳组织区。距离为 1.50--4.00m 时，正常二传仍必须送入攻手的普通起跳带。二传超过 4.00m 时，起跳带随超出距离后移一半：每超过 1m 后移 0.50m，累计后移最多 1.50m。

### R-OFF-002 攻手起跳带

起跳带从网面向本方量距离。边攻、接应和 3v3 `Attacker` 为 0.75--1.50m；副攻为 0.50--0.75m。实际传球可在相应带内并作有限横向修正，但不能把实际传球接触点的深度直接写成起跳深度。

### R-OFF-003 最佳传球意图与二传技术

在最佳组织区，每次正常二传都瞄准攻手起跳带内、预测拦网手臂处理空间最大的合法处理点；不得通过概率故意选择次优目标。二传技术只影响围绕该意图的有界横向、深度、高度和到达时间误差，以及可维持的合法节奏。

误差必须随困难度可解释地增大：二传离网距离、横向位移、背传/紧急动作和助跑剩余时间越不利，误差越大。实际传球仍须通过物理飞行求解与 A--E 传球质量评估。

### R-OFF-004 助跑连续性

一传已使二传职责和预期攻手可确定时，攻手立即朝助跑起点移动。二传确认后，攻手继续向预备点和起跳点推进。实际二传接触后的重规划只能作有界纠偏，必须保留已累计的助跑进度，不能重置到远离网的中性位置。

### R-OFF-005 几何驱动进攻

攻击 AI 依据预测的激活拦网臂胶囊体，比较合法直线、斜线、慢速过手和手臂边缘路线。候选线路必须满足可达性、合法越网和合法落点；手臂碰撞只由真实物理响应改变球路，随后仍按 R-REF-005 判分。

## 修改检查清单

修改任何比赛规则前，作者必须确认：

1. 修改的是既有规则 ID，而不是复制或新建同目的规则；
2. 新文本未与更高优先级规则冲突，尤其不能绕过 R-REF-* 或 R-GOV-*；
3. 规则结果不依赖硬随机、概率分支或不可重放的外部输出；
4. 代码、单元测试、场景测试、规格和变更记录已同步；
5. 若保留临时偏差，已加入符合性清单且有明确移除路径。
