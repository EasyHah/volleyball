# 球员生涯领域规则基线

- 状态：首个技术闭环实施基线
- 适用范围：Career Domain、Application、Content、MatchIntegration 与相关测试
- 不负责：Unity 页面布局、磁盘写入细节、比赛内部模拟

## 1. 设计目标

球员生涯的核心循环是：安排有限时间、参加训练或比赛、按实际行为获得成长、承受疲劳与
状态后果，再进入下一周。领域规则首先服务排球运动员的比赛生涯，不扩张成大学生活模拟、
关系网模拟或自由加点 RPG。

市场参考只用于验证设计原则，不复制其内容规模：EA Sports FC 26 将训练方向与比赛中哪些
行为获得更多经验相连；MLB The Show 的 Road to the Show 让场上行为自然推动对应能力成长；
College Football 的学生生涯则证明非训练活动只有在存在明确期限和参赛后果时才形成有效
取舍。参考资料：[EA Sports FC 26 Career Deep Dive](https://www.ea.com/games/ea-sports-fc/fc-26/news/pitch-notes-fc26-career-mode-deep-dive)、
[Road to the Show 官方说明](https://blog.playstation.com/2018/03/08/whats-new-in-mlb-the-show-18s-rpg-mode-road-to-the-show/)、
[College Football 25 Road to Glory](https://www.ea.com/news/college-football-25-road-to-glory)。

## 2. 生涯阶段

完整球员生涯仍采用六个赛季：大学阶段两季、虚构 V 联赛职业阶段四季，最后进入退役结算。
模式和入口统一称为“球员生涯”，不得把整体模式命名为“大学生涯”。

首个技术里程碑只执行大学第一赛季第一周，并在周末结算后进入第二周 `Planning`。它验证
规则、保存和交互闭环，不宣称已经验证六赛季节奏与平衡。后续六周玩法验证篇是独立里程碑，
当前不展开其首发竞争、培养方向和长期事件内容。

## 3. 球员基础状态

### 3.1 八项能力

八项能力固定为：

| 能力 | 含义 | 主要成长来源 |
| --- | --- | --- |
| 扣球 | 进攻技术、线路和处理能力 | 扣球专项训练、比赛扣球行为 |
| 发球 | 发球技术与稳定性 | 发球专项训练、比赛发球行为 |
| 接发 | 一传判断与到位能力 | 接发专项训练、比赛接发行为 |
| 防守 | 后排防守与救球能力 | 防守专项训练、比赛救球行为 |
| 拦网 | 拦网判断与手型 | 拦网专项训练、比赛拦网行为 |
| 移动 | 场上启动、覆盖与制动 | 移动力量训练、比赛移动负荷 |
| 弹跳 | 起跳能力与重复起跳质量 | 弹跳力量训练、比赛跳跃事实 |
| 体能 | 维持比赛质量和恢复的能力 | 体能力量训练、比赛工作负荷 |

界面显示 `1–100`。Domain 自有 `CareerPlayerAttributes` 使用八项 `0–10000` 整数能力基点，并单独累计
各项成长经验；不得保存 Shared 的 `PlayerAbilitySnapshotV1`，也不得通过
持续累加浮点数保存长期成长。首版显示换算为
`Clamp((abilityBasisPoints + 50) / 100, 1, 100)`（整数除法）；进入正式比赛契约时仍传递带明确量纲的
定点整数，由契约版本规定其范围。旧 `MatchContextV1` 如仍需 `[0,1]` 浮点，只能存在于临时适配层，
不得写入正式存档或新版规范哈希载荷。

能力值、成长经验和所有换算必须有明确上下界。达到上界后的多余经验如何处理属于成长规则，
不得依靠整数溢出或静默截断。

### 3.2 简化潜力

首个里程碑只实现一个玩家可见的综合潜力等级：`D / C / B / A / S`。潜力暂时只提供版本化的
整体成长效率修正，不保存八项隐藏上限、潜力区间、可信度或球探揭示进度。

未来复杂潜力系统通过新规则版本与存档迁移加入。当前不得预先创建没有调用方的空服务接口，
也不得把未来字段塞入未定义语义的字典。

### 3.3 疲劳

疲劳为玩家可见的 `0–100` 整数，`0` 表示充分恢复，`100` 表示无法继续承受正常负荷。
训练和比赛增加疲劳，休息降低疲劳，体能能力影响负荷与恢复的换算。

疲劳只降低临场有效能力和稳定性，不永久扣除八项基础能力。首个里程碑不实现伤病、带伤出战、
恶化和长期缺阵；这些属于后续独立里程碑。

### 3.4 心态

心态为玩家可见的 `0–100` 整数：

| 数值 | 显示状态 |
| --- | --- |
| 0–19 | 低迷 |
| 20–39 | 紧张 |
| 40–59 | 平稳 |
| 60–79 | 自信 |
| 80–100 | 火热 |

比赛表现、连续失误、关键球、教练信任和事件选择可以改变心态。心态主要影响发挥稳定性和
关键分表现，不直接永久增加能力。休息可使极端心态向平稳区间恢复；系统不得让心态无理由
每周固定下降，迫使玩家重复维护。

### 3.5 教练信任

教练信任为玩家可见的 `0–100` 整数。大学试训生成初始值；团队合练、战术执行、比赛稳定性
和事件选择会改变它。第一周正式比赛保证主角获得出场机会，避免低信任阻断技术闭环。

首个里程碑只完整记录和解释信任变化，不实现复杂关键球分配、承诺系统或长期首发竞争。

## 4. 大学试训

新建球员只要求球员姓名、球衣号码和生涯名称；玩家位置固定为主攻，`careerSeed` 自动生成。
外观、身高体重、惯用手、背景故事和打法类型不进入首个里程碑。

试训由三个顺序选择组成：进攻测试、接发防守测试和综合对抗。选择与版本化试训配置共同生成：

- 八项初始能力和成长经验；
- 一个综合潜力等级；
- 初始疲劳、心态和教练信任；
- 进入大学第一赛季第一周所需的稳定状态。

同一 `careerSeed`、规则版本、内容版本和相同选择必须生成相同结果。试训不得要求玩家预选
进攻型、均衡型或保障型。

第三段选择提交成功时一次性建立完整球员、球队归属和第一周 `Planning`。随后显示的初始结果是该提交
的只读投影；“继续”只导航，不执行第二次确认或产生新 revision。

## 5. 每周行动规则

一周固定三个有序行动槽。正式比赛由赛程预留槽位，玩家不能覆盖、删除或移动。确认前可调整
普通行动；确认后整周计划锁定，并由持久化状态机逐槽执行。

首个里程碑的第一周固定为：

1. 槽位 1：玩家选择普通行动；
2. 结算槽位 1 后触发一个固定社交事件样例；
3. 槽位 2：玩家选择普通行动；
4. 槽位 3：正式比赛预留；
5. 比赛结算、周末结算和进入第二周 `Planning` 由同一原子命令完成。

社交事件样例不额外占用槽位。以后事件可以明确锁定或占用槽位，但必须在玩家确认周计划前显示。

### 5.1 常驻行动

常驻行动只包含四类：

| 行动 | 玩家选择 | 直接结果 | 下场比赛关联 |
| --- | --- | --- | --- |
| 专项训练 | 扣球、发球、接发、防守或拦网 | 对应能力经验、疲劳 | 对应比赛行为的成长经验修正 |
| 力量训练 | 移动、弹跳或体能 | 对应能力经验、较高疲劳 | 对应身体事实的成长经验修正 |
| 团队合练 | 首版固定方案 | 教练信任、少量综合经验、疲劳 | 无；首版契约没有独立战术执行事实 |
| 休息 | 无子方向 | 恢复疲劳，极端心态向平稳恢复 | 提高比赛日可用状态 |

专项训练和力量训练同时产生少量直接经验和一个待下一场比赛消费的 `trainingEmphasis`；团队合练只
结算表中列出的直接后果，不生成无法与比赛事实匹配的 emphasis。`trainingEmphasis` 与玩家赛前选择的
`preMatchPriority` 完全独立，不能共用枚举、字段或 UI 名称。比赛成功与否仍由比赛事实决定；emphasis
只调整对应事实结算出的成长经验，不直接保证得分或胜利。

首个 `vertical_slice_v1` 使用按方向聚合的定点整数映射：

- 专项/力量训练首次命中某方向增加 `1000` growth bonus basis points；同一周第二次相同方向只增加
  `500`，该方向上限 `1500`；
- 两次不同方向各自保留完整首次贡献，不互相覆盖；休息不产生 emphasis；
- 每项记录来源 `slotActionId`，聚合结果在创建 `PendingMatch` 时冻结；只有下一场比赛首次成功结算才在
  同一 revision 消费并清除，失败/取消/重试都不得提前或重复清除。

两次行动的直接经验和疲劳仍分别完整结算；边际递减只应用于上述下场比赛成长 bonus。以后调整数值
必须提升 `rulesetVersion` 或内容版本并更新 fixture。

首个一周闭环使用配置规定的固定负荷。后续玩法验证篇才加入“标准 / 高强度”两档。负荷和成长修正
全部来自版本化规则，不散落在 UI 或 ScriptableObject 的运行时状态中。

学业和社交不是常驻行动。大学阶段的学业以后通过考试、补课或奖学金事件制造阶段性时间压力，
不建立 GPA 或独立学业养成树。社交始终通过具体人物和情境事件出现。

## 6. 事件规则

事件模板、选项和结果拥有不可复用的稳定业务 ID。每次事件实例首次创建时分配并保存
`occurrenceId`；重新载入、重新排序或重试不会改变它。

首个里程碑只实现一个球队社交事件，包含两个选项和一次有界的确定性随机结果。这个固定样例只可
影响：

- 心态、疲劳和教练信任；
- 与排球直接相关时，增加少量对应能力成长经验。

未来事件可以影响特定队友默契、后续事件条件、行动槽或通知，但必须在相应系统有真实调用方时通过
规则和 schema 版本加入；首个样例不创建这些字段或空接口。

普通聚会或对话不得直接随机增加扣球、弹跳等永久能力。选择前应显示主要收益和风险方向，
具体数值可在配置上限内变化。相同存档状态与相同选择必须得到相同结果，不能通过反复读档刷新。

## 7. 训练与比赛表现联动

比赛模块报告不可变事实，Career 计算成长后果。下一版 Shared 比赛结果契约至少需要支持：

| 能力 | 需要的比赛事实 |
| --- | --- |
| 扣球 | 尝试、得分、失误 |
| 发球 | 尝试、直接得分、失误 |
| 接发 | 次数和质量分布 |
| 防守 | 救球尝试和成功 |
| 拦网 | 尝试、有效触球、直接得分 |
| 移动 | 覆盖距离或规范化移动负荷 |
| 弹跳 | 跳跃次数和高负荷跳跃 |
| 体能 | 出场回合和总工作负荷 |
| 稳定性 | 关键分表现和连续失误片段 |

`origin/main@4bf9e4b` 的 `FormalIndoor6v6` 已能为 12 名球员产生 V1 的
`points/contacts/errors/workload`，证明身份和单局结果管线可复用；但这些汇总值不能唯一推导上表任何
技术动作的尝试、质量或负荷细分，当前 Bootstrap 也按位置模板覆盖上下文能力。该字段集合仍是 Shared
升级讨论的最低输入需求，Match 必须从真实计分、触球、移动和起跳事件记录，并真正消费 Career 映射的
能力，不得由 Career 对 V1 汇总值猜测拆分。契约升级由双方在独立跨模块分支中确认版本、规范哈希和
12 人 fixture。

赛前重点只提供“优先进攻、保障一传、控制体能”三项。首个里程碑的 FakeMatch 事实固定，重点只改变
Career 对相同事实的成长权重、疲劳转换或赛后解释，不反向修改比分和统计。未来直接比赛或快速模拟
是否消费重点来改变过程倾向，留到 Shared 联合评审后定义；两者最终必须产生同一结构的事实报告。

## 8. 确定性随机

Domain 禁止直接调用 `UnityEngine.Random`，也不使用依赖全局调用顺序的 `System.Random`。
`careerRandomAlgorithmVersion = 1` 的 `careerSeed` 是创建生涯时生成的 32 字节值，在 JSON 中保存为
64 个小写十六进制字符；解析后长度不等于 32 字节或含非十六进制字符必须拒载。稳定键为：

```text
careerSeed
+ streamId
+ season
+ week
+ entityId
+ occurrenceId
+ drawIndex
```

正式 TLV 字节、拒绝采样和 golden vector 以 `career-save-and-recovery.md` 第 7.2 节为唯一规范。现有
`streamId` 不得改义或复用；首个里程碑只注册有真实随机调用的 `tryout`、`event` 和 `match_seed`，各流
实际键、范围与输出解释以该文档的正式调用注册表为准。训练结算完全确定，不注册 `training` 流；没有
调用方的未来流不提前实现。

固定测试向量必须覆盖正式文档向量、相同键、字段边界碰撞、插入无关行动、行动重排、删除重建、
多实体同周、拒绝采样和重启复算。确定性承诺覆盖生涯规则、事件和相同比赛事实下的结算，不承诺
Unity 物理比赛逐帧复现。

## 9. 领域不变量

- 能力、疲劳、心态和信任始终处于各自合法范围；
- Career 属性模型不包含 Shared 比赛能力 DTO；映射只发生在 MatchIntegration；
- 一周始终恰好三个槽，比赛预留槽不能被普通行动修改；
- 已确认计划不能编辑，已完成行动不能回退；
- `weekPlanId`、`slotActionId`、`occurrenceId` 和各操作 ID 非空且在所属范围内唯一；
- 同一行动或事件的后果只应用一次；
- 训练、事件、比赛结算和周末结算不直接写磁盘，也不发布半完成状态；
- ScriptableObject 只提供静态配置，运行时进度只存在于生涯快照；
- UI 只提交命令，不直接设置领域字段；
- 类型评价和培养方向不进入首个一周闭环，不用临时枚举或空字段占位。

## 10. 首个里程碑领域验收

EditMode 测试至少覆盖：

- 八项能力和四个状态的边界；
- 相同试训输入产生相同球员，第三段后“继续”不创建额外 revision；
- 三槽、比赛预留、确认锁定和稳定 ID；
- 四类行动的方向、经验、疲劳、心态与信任后果；
- 专项/力量训练的 `trainingEmphasis` 对同方向 `1000 + 500`、不同方向并存、上限、冻结、首次
  成功结算消费和重试幂等；`preMatchPriority` 保持独立；
- 社交事件两个选项、随机上限、重载复算和不可刷结果；
- 同一 FakeMatch 事实重复提交不会重复成长；
- 周末结算后进入第二周且所有状态合法。

长期平衡不是首个里程碑验收项。当前数值配置标记为 `vertical_slice_v1`，只要求方向合理、反馈
可见、无固定溢出和可复现；六赛季成长曲线在闭环可反复试玩后另行验证。
