# AI 控制的物理触球与流畅动作升级计划

> 状态：需求讨论稿。本文吸收 `volleyball-fps-prototype` 的训练经验，作为
> 现有 `AiRallyPrototype` 的第二阶段升级计划。原计划记录已经完成的可读性原型，
> 本计划替代其中“预设球弧 + 单次姿势插值”的运动与触球方案。

## 目标

把当前由 `BallFlight` 直接插值球位置、角色切换关键姿势的演示，升级为：

- 球是唯一持续积分的动态物理对象；球在触球之间不被动画或导演直接改位置。
- AI 预测球的未来轨迹，安排球员移动、起跳和动作时序，但不能凭空保证触球。
- 垫球、二传、扣球分别使用绑定在骨骼上的有限几何接触面。
- 只有球的扫掠轨迹真正穿过已激活的接触面，才产生一次合法触球。
- 出球速度由物理反射、接触面运动和 AI 目标速度共同决定。
- 动画以预计触球绝对时间为中心，包含准备、发力、触球、随挥和恢复阶段。
- 保留受限的技术控制修正，用来抽象未建模的前臂形变、手指连续施力和身体力量传递；
  修正必须可观察、可测试，禁止瞬移球或在未接触时启动下一段轨迹。

这里的“拟真物理”指球的重力、阻尼、接触、反弹、球网和地面结果具有连续且
可解释的运动规律；第一阶段不要求六名球员成为受力刚体或 ragdoll。

## 不能原样迁移的部分

1. **不迁移第一人称相机根节点。** 接触面必须来自第三人称角色骨骼和球场局部
   坐标，而不是写死世界 `-Z`。
2. **不沿用可变帧长直接积分。** 训练项目只限制最大 `dt = 1/30s`，本项目改用
   固定步进累加器；渲染帧只插值显示。
3. **不忽略接触面速度。** 训练项目的快速挥臂不会给球额外能量。本项目使用球与
   接触面的相对速度计算反射，再把接触面速度和动作发力传回球。
4. **不让预测器复制另一套公式。** 预测器、落点求解器和运行时必须调用同一个
   `BallIntegrator.Step`，防止长轨迹漂移。
5. **不使用忽略阻尼的发球解。** 目标速度求解必须包含实际阻尼，并通过运行时
   步进回放验证误差。
6. **不把技术控制等同于瞬移。** 训练项目的全辅助只作为对照；新系统即使使用最高
   技术控制，也仍要求动画接触面真实命中球并遵守动作方向和力量边界。
7. **不假设已经拥有完整排球物理。** 自旋、Magnus 效应、网面形变、球员刚体和
   角色间碰撞均需要单独立项，不能由这次迁移暗示已经实现。

## 物理与技术控制契约

### 固定步进

建议初始物理频率为 `120Hz`，以覆盖高速扣球。每个子步严格执行：

```text
copy position -> previousPosition
apply gravity
apply air damping
predict next position
find earliest swept collision in this substep
resolve contact and remaining substep time
commit position and velocity
decrease contact cooldown
```

渲染、动画和 AI 可以按帧更新，但触球判定只读取固定步进时刻的骨骼接触面快照。
所有模拟时间使用同一个时钟；慢动作只缩放模拟时钟，不允许角色移动继续使用未缩放
墙钟时间。

### 接触响应

训练项目的基础公式保留为可比较基准：

```text
reflected = reflect(incoming, normal) * bounceStrength
outgoing  = lerp(reflected, assistedTargetVelocity, assistCorrection)
```

本项目升级为移动接触面版本：

```text
relativeIncoming = ballVelocity - surfaceVelocity
relativeReflected = reflect(relativeIncoming, normal) * restitution
physicalOutgoing = relativeReflected + surfaceVelocity * velocityTransfer
outgoing = lerp(physicalOutgoing, techniqueTargetVelocity, techniqueControl)
```

- 垫球先以训练项目的 `bounceStrength = 0.85`、`assistCorrection = 0.35`
  作为迁移对照，不作为新系统的全局 AI 配置。
- `techniqueControl` 由动作允许上限、球员对应技术属性和实际接触质量共同计算；
  不能成为碰撞器常量，也不提供全局“AI 辅助百分比”滑杆。
- 出球后只允许沿法线做最小穿透修正，不允许把球强行放到目标轨迹起点。
- 双手和双臂属于同一个 `contactGroup`，共享冷却，避免一次动作被计为两次触球。

```text
techniqueControl
= actionControlLimit
× playerTechnique
× measuredContactQuality
```

动作边界：

| 动作 | 技术控制上限原则 |
| --- | --- |
| 垫球 | 中等；补偿身体发力与前臂形变，但平台法线必须主导球路。 |
| 二传 | 较高；抽象手指与双掌的连续施力，但球必须进入额头上方双手区域。 |
| 扣球 | 较低；手掌线速度和挥臂方向主导，只允许在实际击打方向附近修正。 |
| 拦网 | 接近零；主要由来球与手掌的被动反弹决定。 |
| 发球 | 中低；允许主动技术控制，但手掌方向、速度和力量上限必须成立。 |

- 每个动作配置最大方向修正角、最大速度增减和最大出球速度。
- 技术控制不能反转实际击打方向，不能把擦边触球变成完美球，也不能超过球员力量
  允许的速度。
- 球离开接触面后不再修正；完全未接触时 `measuredContactQuality = 0`。
- 调试数据同时记录 `physicalOutgoing`、`techniqueTargetVelocity`、最终速度和实际控制量。

### 空气、摩擦与旋转

- 空中使用重力和线性空气阻尼；“摩擦力”只在球与地面、球网或身体表面接触时
  参与切向速度衰减。
- 地面具有恢复系数和切向摩擦，落地后立即按排球规则结算，不模拟长期滚动。
- 球网第一阶段使用有限厚度的静态几何网面和上沿带，不模拟布料形变。
- 第一阶段不加入自旋，以无自旋的重力、阻尼、移动接触面、球网和地面结果作为核心
  验收基线；不得用隐藏横向修正冒充旋转。
- 核心验收通过后再独立加入角速度、接触摩擦力矩、角阻尼和 Magnus 力。自旋运行时
  与预测器必须使用同一个固定步进模型，并能通过配置完全关闭以对比无自旋基线。

## 三类核心动作的接触定义

### 已确认的角色表现方案

- 第一阶段继续使用增强版程序化简化人体，不引入 Humanoid 模型、Avatar、动作重定向
  或外部排球动画资产。
- 角色采用可信的人体比例、清晰的肩/肘/腕/髋/膝/踝关节和简化手掌；不追求肌肉、
  手指或专业运动员动作的 100% 还原。
- 全身动作以流畅、可辨认和节奏正确为目标；前臂平台、二传双手和扣球手掌是需要
  精确对球的高约束区域。
- 非触球关节的细微误差只影响观感；触球位置、法线、时机或表面速度不正确时，必须
  降低接触质量和目标技术控制，使球速或落点产生相应偏差。
- 动作、IK 和接触面通过语义部位接口连接，未来若切换 Humanoid，只替换骨骼适配与
  渲染层，不重写球模拟、AI、动作时间线和接触响应。

## 球员属性与动作误差契约

球员属性必须在本阶段预留为基础架构。属性不在触球完成后直接给球叠加随机偏差，
而是影响角色本次动作的可见执行结果，再由实际接触产生球路差异：

```text
PlayerAbilityProfile
  -> SkillExecutionResolver
  -> 本次反应、时机、接触位置、法线和表面速度误差
  -> 动画、IK 与骨骼接触面
  -> 真实扫掠碰撞
  -> 物理出球与受限技术控制
```

第一阶段的最小属性集合：

| 属性 | 影响 |
| --- | --- |
| `Mobility` | 最大移动速度、加速度、制动和可达范围。 |
| `Reaction` | 开始移动、选位和进入动作准备阶段的延迟。 |
| `Jump` | 起跳速度、最高触球高度和可用滞空时间。 |
| `ReceiveTechnique` | 前臂平台位置、法线稳定性和一传目标控制。 |
| `SetTechnique` | 双手接触时机、传球高度和二传目标控制。 |
| `AttackTechnique` | 手掌触球位置、挥臂方向和击球时机。 |
| `AttackPower` | 击球手掌表面速度和最大合理出球速度。 |

身高、臂长、肩宽和手掌尺寸属于身体配置，直接改变几何可达范围，不与技术属性混为
同一个数值。疲劳、状态、士气和临时增益以后作为属性修正层叠加，本阶段只保留接口。

`SkillExecutionResolver` 为每次动作生成可重放的执行误差包：

```text
SkillExecutionError
- reactionDelay
- contactPositionError
- contactNormalError
- contactTimingError
- surfaceSpeedScale
- targetVelocityError
- maximumTechniqueControl
```

约束：

- 执行误差必须应用到实际动作、IK 和骨骼接触面，禁止只移动不可见的数学碰撞面。
- 同一种误差只施加一次；如果接触位置已经偏移，出球阶段不能再次重复惩罚同一偏差。
- 最终技术控制量为“动作控制上限 × 实际接触质量 × 球员技术系数”。
- 完全未接触时技术控制为零；擦边接触只能获得有限控制；正确接触才可获得完整控制。
- 所有误差使用独立的固定种子随机流，同一球员、回合、动作和种子必须能够重放。
- 第一阶段六名球员可以使用相同默认属性，但运行时代码不得绕过属性接口读取硬编码
  完美值。

### 防守垫球

- 接触几何：两前臂之间的有限矩形平台，尺寸从骨骼世界位置实时生成。
- 动作阶段：移动到位 → 降低重心 → 双臂合拢 → 平台激活 → 触球 → 随挥 → 恢复。
- 平台法线来自两前臂方向和角色朝向，不使用固定世界上方向。
- 预计触球前才进入激活窗口；使用 `0.6 / 0.4` 滞回防抖。
- 球必须与前臂平台相交，慢放时接触误差不得超过球半径加容差。

### 二传上手传球

- 接触几何：左右手掌各自的有限平面或椭圆面，组成一个共享冷却的双手接触组。
- 动作阶段：移动到球下 → 屈膝举手 → 手形成窗口 → 短接触发力 → 手腕随动 → 恢复。
- IK 目标是预计触球时的球心两侧，而不是当前球位置，避免双手追球抖动。
- 出球目标速度由攻手预计击球点反解，双手和腿部伸展速度进入表面速度。
- 不允许“吸住”球等待动画；接触持续时间和位移必须保持为一次连续击球。

### 进攻跳跃与挥臂

- 接触几何：击球手掌的有限平面或短胶囊，绑定到手腕和手掌方向。
- 动作阶段：两到三步助跑 → 制动起跳 → 手臂后引 → 肩肘连续挥动 →
  最高点附近触球 → 向下随挥 → 双脚落地缓冲。
- 跳跃由可预测的运动曲线驱动角色根节点，不在触球帧瞬间抬高角色。
- 手掌速度必须进入球的接触响应，使更快挥臂产生更高出球速度。
- IK 只在触球前的有限窗口修正肩、肘、腕，不得无限拉伸或破坏随挥曲线。
- 如果手掌没有命中球，动作应判定挥空，不能由导演补发扣球轨迹。

## 运行时顺序

```text
读取当前球状态
  -> 轨迹预测与预计落点
  -> AI 选择接球人、动作和目标区域
  -> 检查角色在目标时间是否可达
  -> 移动、助跑、起跳并调度动作阶段
  -> 从骨骼生成上一/当前接触面快照
  -> 固定步进积分球
  -> 求本子步最早的地面/球网/身体接触
  -> 若触球，应用物理与技术控制混合速度
  -> 若落地或出界，结算一次得分
  -> 动作随挥、恢复并开始下一次预测
```

当同一子步存在多个候选碰撞时，按最早碰撞时间处理，而不是固定让地面或手臂
永远优先。一次子步最多处理有限次数碰撞，超过上限立即记录诊断，避免死循环。

## 第一阶段验收标准

1. 垫球、二传和扣球在 0.25 倍慢放下均能看到球模型与对应接触面真实相交。
2. 球在触球之间只受积分器、空气阻尼和静态环境碰撞影响，没有 Transform 插值轨迹。
3. 垫球平台、二传双手和扣球手掌的动作与预计触球时间同步，没有球等待角色。
4. 攻手具有可读的助跑、起跳、后引、挥臂、随挥和落地，不是整体平移后切换姿势。
5. 同一输入和固定步进可重现相同的接触序列；浮点位置允许小容差。
6. 技术控制可以提高目标落点准确率，但关闭技术控制后仍保持正确的物理反射；开启后
   不得突破动作方向、力量和真实接触质量的边界。
7. 未真实命中的动作会失败；导演不得通过补帧、吸附或重新放置球制造成功。
8. 球网和地面结果来自最早扫掠碰撞，快速球不能穿透。
9. 相同来球下，高低技术属性通过可见动作误差产生可测量的球路差异；相同属性和种子
   可重现相同结果。

## 已确认与待确认决策

- **角色资产（已确认）：** 第一阶段使用增强版程序化简化人体；全身动作强调流畅和
  可读，技术动作的正确接触部位强调几何准确。Humanoid 仅作为核心系统完成后的可选
  外观升级。
- **球员属性（已确认）：** 现在预留属性与动作误差解析系统。属性通过可见的反应、
  时机、接触位置、法线和表面速度影响球路，不在触球后追加不可见的随机偏差。
- **旋转（已确认）：** 第一阶段不加入自旋；先验收无自旋的重力、阻尼、球网和真实
  动作接触，再按 Task 11 独立加入角速度、接触力矩和 Magnus 效应。
- **技术控制（已确认）：** 不设置独立的 AI 辅助强度。使用受动作类型、球员技术属性
  和真实接触质量共同限制的 `TechniqueControl`，用于抽象简化人体未建模的生物力学；
  垫球中等、二传较高、扣球较低、拦网接近零、发球中低，具体数值由测试调优。
- **玩家刚体：** 默认角色保持运动学控制，不模拟球对角色的反作用力，也不加入角色间
  刚体碰撞；这不影响球与骨骼接触面的物理连续性。
- **确定性边界：** 自研固定步进可提高单机重放稳定性，但加入 Unity Rigidbody、布料网
  或跨平台网络同步后需要重新定义确定性保证。
