# 训练室阵容编辑、严格位置错误与 V5 接线设计

- 日期：2026-08-01
- 状态：已确认界面与规则设计；待独立高风险任务单激活
- 范围：TrainingLab 阵容/发球前布置 UI、严格位置错误判定、V5 正式裁判结果与 Replay 证据

## 目标

将训练室从情景参数编辑器扩展为可复现的发球前布置工作台。开发者先确定双方六人轮转，随后直接拖拽
球员摆站位、设置发球球的初始位置和速度，并由同一套严格位置错误规则在训练室预览和 V5 正式比赛中
消费。违反位置错误的队伍在发球触球瞬间立即丢分。

训练室管理员可为当前情景覆盖 Match 测试属性；这些覆盖永远不写回 Career、V5 权威档案或正式比赛。

## 非目标

- 不修改 V4 历史恢复、其规则、存档、结果或回放。
- 不实现回合中任意插入球状态；训练室只从发球前开始。
- 不允许训练室属性覆盖进入 V5 context、Career 存档或正式比赛。
- 不提供位置错误容差、手工改写裁判结果或绕过判罚的开关。
- 不编辑球员姓名、号码、职业/注册位置或 Career 权威属性。

## 术语与规则

- **轮转位次**：每队六名上场球员的 1--6 号法律身份；先编辑、确认后锁定。
- **实际站位**：发球触球瞬间球员脚部投影的场地坐标；拖拽只改变实际站位，不改变轮转位次。
- **位置错误**：同队球员的前后或左右相对关系被实际反转。投影相等合法；仅严格反转违法。实现可使用仅为
  浮点稳定性服务的非配置化极小比较值，不能形成用户可调容差。
- **发球球状态**：当前发球方在己方底线后的球位置和初速度。球不能保存、校验或运行在场内或对方底线后。

位置错误仅在发球触球瞬间裁决。若 Home 或 Away 有任一违法关系，裁判立即判该队失回合，对方得一分，
触球计数保持 0，不进入正常回合物理和决策流程。

## 训练室界面

采用五步工作台，而不是把轮转、摆位、球和裁判状态混在一个可随时修改的页面中：

1. **轮转**：每队查看并保留或编辑 1--6 位次。场上与列表均显示注册职业，如二传、主攻、副攻、接应
   和自由人。确认后锁定；若返回修改轮转，既有实际站位失效，必须重新确认。
2. **摆位**：主球场支持拖拽 12 名球员。每个头顶标签显示职业和锁定的位次。即时裁判器用红色标记参与
   违规关系的球员，并以自然语言说明哪两位球员、哪条前后/左右关系错误及修正方向；此时不计分。
3. **发球球**：三个互斥工具模式为“移动发球球”“调整发球速度”“查看发球轨迹”。黄色球只在移动工具
   可拖拽；红色速度箭头只在速度工具可拖拽；轨迹工具只读。精确 X/Y/Z 与 VX/VY/VZ 输入始终存在，但
   只有当前工具相关字段高亮。正交视图分别编辑 XY、ZY、XZ 的位置或速度双轴；三视图实时同步一份
   六轴数值。
4. **校验**：冻结轮转、站位、发球方、发球球状态和训练属性覆盖；位置错误、边界、球员/球重叠等错误
   会阻止运行。
5. **运行**：发球触球时再次执行权威位置错误判定，之后才进入正常正式回合。运行中所有编辑只读。

回合监视器跨步骤持续显示当前阶段、发球方、触球计数、最后合法触球者、球状态、校验/判罚状态与下一步
操作。自由视角只用于观察，可作为命名机位保存到训练情景；不改变球、阵容或正式比赛数据。

## 管理员属性覆盖

管理员使用每队一张横向可滚动的表。姓名、注册职业与锁定轮转位次只读。可编辑列为 Match 测试数值能力、
身高和惯用手；已覆盖的字段使用黄色描边，未覆盖字段沿用情景默认测试值。

覆盖在校验时推导为该情景私有的 Match 测试快照，并随情景保存。它不写入 Career、不修改 V5 base/derived
权威值、不成为正式 V5 context 的输入，也不改变其他训练情景。

## V5 正式接线

TrainingLab 与 V5 共用一个 Match 所有的、纯函数式严格位置错误判定器。训练室传入冻结轮转和发球前站位
用于预警与运行前校验；V5 传入正式阵容、当前轮转和发球触球帧站位用于权威裁决。两者不能互相读取各自
的情景、存档、镜头或管理员覆盖。

正式 V5 的位置错误产物至少绑定：违规队、得分队、发球方、轮转位次与相关球员、被违反的相对关系、
触球时的脚部投影采样、rally/session/context identity，以及确定性规则版本。`MatchResultV5` 和
`MatchReplayV5` 记录同一事实并受现有 context/result/replay hash 绑定；Career 只能消费最终比赛事实，
不能重新判定位置错误。

## 展示与失败处理

训练室预警用可修正语言，例如“Home 的 4 号二传比 5 号主攻更靠后；将 4 向网前拖动或将 5 向后场拖动”。
正式判罚显示“位置错误 - Home 丢分”，并固定违规关系、得分队和下一次发球。回放展示该事实和证据，不能
由 UI 或训练室重写。

无效轮转、越过底线的球、非有限数值、球员/球重叠、未冻结轮转或位置错误均使训练室不能开始。V5 中若
位置快照、轮转或证据不完整，启动/裁决应安全失败，不得默默跳过规则。

## 验收与验证

- 训练室：轮转锁定/重新编辑、球员拖拽、职业/位次标签、发球区硬边界、三视图两轴编辑、自由视角命名
  保存、管理员覆盖隔离与回合监视器的 EditMode/PlayMode 测试及人工 UI 验收。
- 规则：各类前后/左右合法、相等、反转与多重违规的纯规则向量；裁判立即失分且触球数为 0。
- V5：成功的正常发球、Home/Away 位置错误、固定种子重放、result/replay 绑定拒绝和 Career 只读消费。
- 数据边界：静态依赖扫描证明 TrainingLab 覆盖、镜头和 Editor 数据不能进入 Career/V5 正式 context；
  V4 行为保持不变。
- 高风险阶段需要 Shared/Career/Match 受影响测试、完整 EditMode、必要 PlayMode、独立复核和 Windows
  Development IL2CPP/Player 验收。

## 实施前置条件

实施前必须创建并激活专用高风险 handoff，明确 Shared/Match/Career/Replay 所有权、V5 版本兼容、回滚和
迁移策略。当前 HUD/审核入口任务不授权本设计的正式规则实现。
