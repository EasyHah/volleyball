# 二传教师审核流水线设计

- 日期：2026-07-31
- 状态：已确认，实施计划已就绪
- 范围：Match Editor / TrainingLab / MenShen / 本地标注数据

## 目标

在 Unity Editor 中为训练实验室的二传目标决策建立受限的“教师建议 -> 人工确认”闭环。现有
MenShen 接口只离线分析一条在 Gate I 攻手选择点冻结的 `SetterTargetSnapshotV1`，为本地逻辑已经生成的合法攻手候选
排序并给出理由。开发者接受建议或选择另一合法候选后，系统写入可用于后续学生模型的数据记录。

## 权威与信息边界

- 仅消费 Gate I 的冻结 `SetterTargetSnapshotV1`；它来自 `AttackPreparationDecision`，候选语义是攻手。
  `DecisionSnapshotV1 (Organize)` 的候选语义是组织者，保持不变且不进入本流水线。
- 教师请求使用本地二传判断时可见的字段：球位置/速度、预测目标、可用时间、已计数触球、最后合法
  触球者、队伍、规则与特征版本、以及本地已排序的可行候选及其评分分量。
- 请求不得包含完整 Replay、未来物理采样、隐藏最终路线、对方内部状态、裁判结果或回合结束后数据。
- 教师只能返回候选 ID 的全排序和面向审核者的理由；不能生成动作、修改候选、提交 contact 或控制
  运行中的实体。
- 教师、审核界面和数据集均只存在于 Editor assembly；正式运行时、Player、Shared、Replay 与 Career
  没有网络依赖或标签写入。

## 数据流

`SetterTargetSnapshotV1 (Gate I) -> SetterTeacherRequestV1 -> MenShen -> SetterTeacherResponseV1
 -> HumanReview -> SetterLabelRecordV1 -> local JSONL dataset`

请求和记录都包含 snapshot hash、候选集 hash、规则/特征版本。教师响应额外冻结模型 ID、提示词
版本、原始响应、请求时间和客户端状态；人工记录冻结最终候选、是否与本地/教师一致、可选理由及
人工确认时间。历史记录不可就地改写；重试创建新的教师尝试，且不得改动已确认标签。

## 审核体验

训练实验室的只读决策快照列表提供“审核二传”入口。审核视图显示本地选择、教师首选、完整候选
排序、评分输入和教师理由。用户只能：接受教师首选，或从当前候选列表选择其他可行攻手；后者可
填写原因。未成功得到且通过严格解析的教师响应时，确认按钮禁用。

首期逐条审核，不提供批量教师预标注或抽检。只有人工确认记录进入黄金集。

## 存储与安全

数据集固定写入被 Git 忽略的 `TestResults/TrainingLab/SetterLabels/` JSONL。每行是完整不可变记录；
教师原始响应仅存于该本地数据集。仓库只保存不含样本、密钥和原始响应的清单，记录 schema 版本、
数据集版本、样本总数、人工确认数和黄金集数量。API 密钥继续仅从 `MENSHEN_API_KEY` 环境变量读取；
端点沿用现有 HTTPS/localhost 校验。

## 校验与失败

响应必须是严格 JSON，恰好覆盖所有当前可行候选且每个候选仅出现一次。任何未知 ID、重复、遗漏、
非可行候选、额外字段、模型失败或网络失败都生成只读错误状态，不写标签。教师请求超时、限流或
重试不得影响模拟、当前本地选择、Replay 或已保存确认。

## 验证

- EditMode：信息集字段白名单与本地二传可见输入一致；请求/候选 hash 稳定。
- EditMode：正常、未知、重复、遗漏和畸形教师响应的解析及拒绝。
- EditMode：人工接受/纠正、历史不可变、黄金集过滤和 JSONL 规范写入。
- Editor：配置缺失、网络失败、超时、限流和重试只改变审核状态。
- 静态扫描：新网络代码只在 Editor assembly；Player/Shared/Replay/Career 无新增依赖。

## 后续

教师审核闭环稳定后，另立任务设计批量预标注和抽检；本地学生模型影子推理必须在其后独立设计，
不得由本任务提前接入。
