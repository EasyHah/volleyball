# V3 回合组织修复与现有属性基准设计

**日期：** 2026-07-24
**状态：** 用户已确认范围
**范围：** 攻手移动连续性、二传组织区、一传默认目标、二传优先与代传回退、现有运行时属性的固定种子测试及回放诊断

## 1. 目标与边界

本期不重构球员属性架构，不新增 V4 身高、臂展、协调性或派生比赛属性合同。比赛继续消费当前
`PlayerAbilityProfile` 与 V2 兼容路径中已真正生效的字段。

本期交付三个可以直接观察和复现的改进：

1. 攻手到进攻点、起跳和触球的根节点运动连续，不再由接触对齐造成明显的瞬时位移。
2. 二传按固定 2.5 号位组织区等待；正常一传默认送入该区；一传偏离时先由二传移动组织，只有其不可达时才让其他队员代传。
3. 用固定种子、控制变量的测试和赛后回放，说明当前属性实际如何改变比赛。

本期不宣称 V3 的 `AttackControl`、`SoftTouch`、`BlockTechnique`、`CourtAwareness` 已经进入正式比赛；它们不属于本期基准。

## 2. 二传组织区

坐标以进攻方视角定义：网为深度零点，四号位侧边线为横向零点。正式场地的四号位侧边线是
`x = -4.5m`，因此横向距离 `6m` 的默认中心为 `x = 1.5m`。深度以本方网前向后量取。

`SetterOrganizationZone` 是唯一的纯策略来源，提供默认目标、区域等级和距离评估：

| 维度 | 最佳 | 次优 | 最差 |
|---|---|---|---|
| 横向（自四号位侧边线） | `5-7m`，默认 `6m` | `3-5m`、`7-8m` | 小于 `3m` 或大于 `8m` |
| 深度（自本网） | `0-1.5m`，默认 `1.1m` | `1.5-4m` | 大于 `4m` |

默认组织点为 `(x=1.5m, depth=1.1m)`，再由 `TeamCourtFrame` 转换至两队世界坐标。它用于：

- 二传接一传时的预备根节点目标；
- 正常一传的出球目标；
- 回放中的组织区与一传落点质量说明；
- 判断二传是否需要明显移动的共同标准。

现有进攻点、进攻线和“二传实际离网超过 4m 时助跑带后移”的规则保留。后者使用二传实际位置，
而不是默认组织点。

## 3. 一传、二传与代传顺序

收到发球后，正常一传的目标是组织区的可触球中心，而不是当前硬编码的 `SetterPosition` 或
3 米线附近点。

组织阶段按下列顺序决定：

1. 对预测的二传触球点评估注册二传的可达性，使用与决策器相同的移动速度、反应延迟和触球时限。
2. 二传可达时，二传是唯一优先组织者；即使其离默认组织点较远，也应先跑动到实际一传落点组织。
3. 二传不可达时，才以现有候选评分在其他合法、可达的球员中选择代传者。
4. 无合法代传者时，沿用既有救球／失分链路，不伪造二传触球。

二传正在接发时不能同时承担二传；连续触球与 V3 权威规则的限制保持不变。该规则只改变组织者的优先级，不绕过触球规则或物理可达性。

## 4. 攻手移动连续性

当前攻手完成助跑后，在 Power/Contact 阶段可获得最高 `0.70m` 的根节点接触对齐修正。这会让物理可达的助跑在视觉上显得“闪现”。

修复原则：助跑、起跳、触球和落地必须由同一条速度受限的根节点轨迹组成。接触对齐只允许处理小量数值误差，不能替代移动：

- 攻手接触对齐上限降至一个小的显示容差（`0.18m`）；
- 任何剩余误差保留为接触偏差，并通过既有接触/执行结果体现；
- 普通接发、传球和受控处理的既有对齐上限不在本期改变；
- 测试同时断言攻手接触对齐上限和相邻物理样本的根节点位移上限，避免以后重新引入突进。

## 5. 当前属性的基准范围

基准只覆盖已进入正式运行时的属性及明确的现有效果：

| 属性 | 固定测试观测量 |
|---|---|
| `Mobility` | 可达距离、助跑准备度、移动短缺、候选选择。 |
| `Reaction` | 可用移动时间、确定性反应延迟和到位结果。 |
| `Jump` | 助跑评分、可视起跳高度、拦网候选优先度。 |
| `ReceiveTechnique` | 一传/救球执行误差与落点稳定性。 |
| `SetTechnique` | 传球执行误差、传球手型与组织质量。 |
| `AttackTechnique` | 扣球执行误差、扣球控制与攻击候选评分。 |
| `AttackPower` | 扣球候选评分、目标球速缩放与攻击输出。 |
| `MaxAttackReach` | 扣球触球高度、攻击候选的同角色决胜。 |

`ReceiveTechnique` 被现有运行时复用为拦网候选的技术输入、`AttackTechnique` 被复用为发球技术、
且回放当前把 `Jump` 显示为拦网值。这些是现状诊断信息，不会在本期悄然改造成新的属性体系。

## 6. 固定种子基准

新增纯基准夹具或运行器，构造两个完全相同的球员/比赛输入，除一个目标属性或预设档案外不变。
每个对照固定：随机种子、球员编号、轮次、战术权重、站位、可用时间、动作、对手和球路。

最低对照集：

1. `Mobility`、`Reaction`：同一来球与触球时限下，验证高值有更大可达余量或更低延迟。
2. `ReceiveTechnique`、`SetTechnique`、`AttackTechnique`：跨一组固定种子累计执行误差，验证高技术值误差更小；传球额外验证可用手型。
3. `Jump`、`MaxAttackReach`：验证助跑/拦网候选差异、可视起跳或攻击接触高度差异。
4. 技术型主攻与力量型主攻：保持移动、反应、弹跳、接发、传球、进攻摸高相同，只交换高 `AttackTechnique` / 中 `AttackPower` 与中 `AttackTechnique` / 高 `AttackPower`。报告候选分、执行误差和目标速度差异，而非凭单个比分宣称强弱。

只有当完整正式回合可稳定重复时，才增加固定种子小局聚合结果；单属性机制断言是本期主要验收，以免物理随机链掩盖属性效应。

## 7. 回放诊断

回放继续使用当前版本化 replay 契约，并添加兼容的可选诊断字段。赛后页面必须让用户看见：

- 每个球员当前实际消耗的属性：移动、反应、弹跳、接发、传球、扣球技术、力量、进攻摸高；
- 每项决策的候选评分构成、可达余量、动作技术值和最终选择；
- 正常一传的组织区目标、实际落点、区域等级，以及二传是否到位、跑动组织或由谁代传；
- 扣球决策的助跑点、起跳点、计划接触点、实际接触偏差和受限的对齐修正；
- 技术型与力量型主攻的对照名称、固定种子和变更属性，供两段回放并排比较。

回放仅显示实际存在的字段和观测值；不把预留 V3 属性伪装成参与评分的数值。

## 8. 验收

- 纯策略测试验证两队的组织点、最佳/次优/最差区间与默认一传目标。
- 决策测试验证：二传可达时优先；二传不可达时才允许代传；连续触球时二传不得被错误选择。
- 球员接触测试验证攻手根节点对齐最多 `0.18m`，且计划助跑样本连续。
- 现有属性的固定种子 EditMode 基准全部可重复并显示预期单调差异。
- 正式 6v6 回放 PlayMode 测试验证新的组织/属性诊断已序列化并在 HTML 中可见。
- 回归运行受影响的 EditMode、正式 6v6 回合和正式 6v6 回放测试；V3 权威规则测试保持通过。
